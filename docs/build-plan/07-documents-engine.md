# שלב 7: מנוע מסמכים (הצעת מחיר → הזמנה → חוזה → חשבונית)

**ישויות:** `DOCUMENT_TEMPLATE`, `DOCUMENT_TEMPLATE_FIELD`, `DOCUMENT`, `DOCUMENT_LINE`, `DOCUMENT_RECIPIENT`.

**מה נבנה בפועל:**
- מנהל תבניות (1.3.13, US-015): עריכת מלל, שדות (טקסט חופשי/מקושר למידע קיים), שדות חובה, סדר הופעה, תצוגה מקדימה. שינוי תבנית משפיע רק על מסמכים חדשים (FR-4.14).
- מנוע הפקת מסמך מתבנית + `preceding_document_id` ליצירת שרשרת (הצעה→הזמנה→חוזה→חשבונית).
- **Gate עסקי מחייב** (FR-4.3, FR-4.4, FR-8.7, FR-8.8): חסימת הפקת חוזה בלי טופס הזמנה, חסימת חשבונית בלי חוזה חתום — ממומש כ-Policy/Validation שבודק שרשרת מסמכים לפני הפקה.
- טופס הזמנה דיגיטלי: שדות מקושרים מעדכנים את המידע העסקי אחרי שליחה (FR-4.12); חוזה מתמלא אוטומטית משדות ההזמנה (FR-4.13).
- חשבונית: בחירת עוסק פטור בכל הפקה (FR-4.15, FR-4.16, FR-8.9), שורות `DOCUMENT_LINE` (תיאור+סכום חובה), סכום החשבונית = סכום השורות (FR-4.18–FR-4.21), חשבונית אחת לעסקה אחת בלבד (FR-4.21).
- `DOCUMENT_RECIPIENT`: ברירת מחדל = אנשי קשר ראשיים, ניתן להתאים per-שליחה בלי לשנות את הגדרת אנשי הקשר (FR-2.11–FR-2.13, FR-4.8, FR-4.9).
- שליחה כטופס דיגיטלי או PDF, לפי בחירת המשתמשת (FR-4.2).

**כללים עסקיים מרכזיים:** US-007, US-015, FR-4.1–FR-4.22, FR-8.7–FR-8.11.

**תלויות:** שלבים 5, 6.

**בדיקות אוטומטיות (חובה, לא לדחות ל-19):** Feature tests ל-Gate העסקי — ניסיון הפקת חוזה בלי טופס הזמנה נחסם, ניסיון הפקת חשבונית בלי חוזה חתום נחסם, סכום חשבונית = סכום שורות תמיד, חשבונית אחת בלבד לעסקה. אלו השערים העסקיים הכי קריטיים ב-PRD ולכן נבדקים כאן ולא רק ידנית בשלב 19.

**הגדרת סיום:** לא ניתן לדלג על שלב במסמכים; חשבונית תמיד עם עוסק פטור ושורות תקינות; שינוי תבנית לא פוגע במסמכים שכבר יצאו.
