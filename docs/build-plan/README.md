# תוכנית בנייה: מערכת "כפיים" — אינדקס שלבים

מסמך זה מפרק את בניית המערכת (לפי `../prd.md` ו-`../erd.md`) לשלבי פיתוח סדורים, בהתאם לתלויות הטבעיות בין המודולים: תשתית → נתוני ייחוס → לידים → לקוחות → עסקאות → מסמכים → תשלומים → מנויים → אספקה ודיוור → כספים → שכבות רוחביות (חיפוש, דשבורד, אינטגרציות, הרשאות) → מובייל/הגירה/הקשחה.

כל שלב נמצא בקובץ נפרד וכולל: מטרה, ישויות DB רלוונטיות (מ-ERD), מה נבנה בפועל, כללים עסקיים מחייבים (מה-PRD, עם מספרי FR/US), תלויות בשלבים קודמים, והגדרת סיום (Definition of Done) שניתנת לבדיקה.

הסטאק (מ-`../stack.md`): Laravel 13, PHP 8.5, PostgreSQL 18, Livewire, Alpine.js, Tailwind, Docker Compose, Nginx, Queue, Scheduler. בכל שלב שמתאר "מסך" — הכוונה ל-Livewire component.

## סיכום תלויות (מבט מהיר)

```
0 תשתית
 └─ 1 משתמשות/הרשאות/יומן פעילות
     └─ 2 נתוני ייחוס והגדרות (כולל תבניות דואר + seed)
         ├─ 3 קטלוג תוכניות/מארזים (כולל דיסקרימינטור is_subscription_type)
         └─ 4 לידים ──► 5 לקוחות ──► 6 עסקאות ──► 7 מסמכים ──► 8 תשלומים/גבייה
                                                        │                └─► 9 מנויים/אספקה
                                                        │                └─► 10 חומרים/רשימות תפוצה
                                                        └───────────────────────► 11 ספקים/הוצאות/תזרים (תלוי גם ב-7: חשבונית הוצאה)
             (4,5,7,8,10,11) ──► 12 אינטגרציות (Smove/Summit/נחיתה) ┄תלות רכה┄► 13
             (1,4,5) ──► 13 הרשאות עובדת מכירות
             (4,5) ──► 14 חיפוש גלובלי
             (4,6,8,9,10) ──► 15 דשבורד
   16 הודעות מערכת — רוחבי, מלווה מ-1 ואילך
   17 מובייל — אחרי 4,5,8,10,15
   18 הגירת נתונים — אחרי 4–11
   19 הקשחה/QA — אחרון (בעיקר rundown/regression; רוב הבדיקות הקריטיות ונעילות הקונקרנסי כבר נבנות נקודתית בשלבים 6-9)
```

הערה: נעילת עדכון אופטימית לטיפול בעבודה מקבילה בין שתי המשתמשות (FR-8.19) נבנית incrementally בשלבים 6, 8, 9 — לא מרוכזת בשלב 19 כפי שהיה במקור.

## המלצת עבודה

לבנות שלבים 0→11 ברצף ליניארי (זה גם סדר תהליך המכירה בפועל — ליד→לקוחה→עסקה→מסמכים→תשלום→מנוי→אספקה), ואז 12–19 כשכבות רוחביות/גימור מעל בסיס עובד. כך גם ניתן להראות למשתמשות (בעלת העסק/מזכירה) גרסת עבודה חלקית כבר אחרי שלב 8, ולקבל פידבק מוקדם.
