# שלב 2: נתוני ייחוס והגדרות (Reference Data & Settings)

**ישויות:** `STATUS_DEFINITION`, `LEAD_SOURCE`, `PAYMENT_METHOD`, `BUSINESS_ENTITY`, `EXTERNAL_INTEGRATION_SETTING`, `EMAIL_TEMPLATE`, `EMAIL_TEMPLATE_FIELD`.

**מה נבנה בפועל:**
- מסך "הגדרות מערכת" (1.3.13): ניהול סטטוסים (לפי scope: lead/customer/deal/document/payment/subscription/expense/material_delivery), מקורות ליד, אמצעי תשלום, עוסקים פטורים (`BUSINESS_ENTITY`), נתוני העסק.
- עקרון: שינוי הגדרה משפיע על **פעולות עתידיות בלבד** (FR-7.8) — כלומר סטטוסים/מחירים נשמרים כ"snapshot" בזמן שימוש בישויות תלויות (רואים את זה כבר ב-ERD: `program_price_snapshot`, `program_name_snapshot` בטבלת `DEAL`).
- טבלת `EXTERNAL_INTEGRATION_SETTING` (system/is_active/settings json) — שלד קונפיגורציה ל-Smove ו-Summit, ייעשה בו שימוש בשלב 12.
- מנהל **תבניות דואר** (`EMAIL_TEMPLATE`/`EMAIL_TEMPLATE_FIELD`, FR-7.7, FR-7.12): תבניות למיילים שהמערכת עצמה שולחת (למשל מייל אישור ליד אוטומטי מדף הנחיתה — FR-1.18), עם שדות מיזוג (טקסט חופשי/מקושר), בדומה למבנה `DOCUMENT_TEMPLATE`/`DOCUMENT_TEMPLATE_FIELD` משלב 7. **הבחנה חשובה:** אלו תבניות למיילים תפעוליים שהמערכת שולחת ישירות (SMTP), להבדיל משליחת חומרי לימוד ודיוור רשימות תפוצה שמתבצעים תמיד דרך Smove (שלבים 10, 12).
- **Seed data**: לקראת פיתוח/הדגמה — נתוני התחלה מינימליים (2-3 מקורות ליד, אמצעי התשלום הארבעה שהוגדרו ב-PRD, עוסק פטור לדוגמה, סטטוסים בסיסיים לכל scope). רשימה מוצעת בפירוט למטה — **הצעה לאישור בעלת העסק, לא החלטה סופית**, פרט לערכים שכבר מאוזכרים ב-PRD/סטוריבורד ומסומנים ככאלה.

### הצעת רשימת Seed מפורטת

**LEAD_SOURCE** (מקורות ליד):

| ערך | מקור |
|------|------|
| דף נחיתה | מאושר — FR-1.1, FR-1.18 |
| הפניה | מהסטוריבורד (leads.html, design-system.html) — לא מופיע ב-PRD, טעון אישור |
| פנייה חוזרת | מהסטוריבורד — טעון אישור |

**PAYMENT_METHOD** (אמצעי תשלום) — מאושר במלואו, PRD סעיף 4:

הוראת קבע · אשראי · העברה בנקאית · צ'קים

**STATUS_DEFINITION לפי scope** (כולם הצעה, פרט למסומן "מאושר"):

| Scope | סטטוסים מוצעים | הערה |
|-------|------------------|------|
| lead | חדש (ברירת מחדל, **מאושר** FR-1.3) → בתהליך מכירה → מוכנה לסגור / רוצה לרכוש → נסגר ללא מכירה | הרמזור (ירוק/צהוב/אדום, **מאושר** FR-1.5) הוא שכבה נוספת שכל סטטוס ממופה אליה: חדש/בתהליך מכירה=צהוב, מוכנה לסגור=ירוק, נסגר ללא מכירה=אדום. תת-סטטוס "ממתינה לשיחה חוזרת" (**מאושר** FR-1.6) קיים רק תחת צהוב |
| customer | פעילה → לא פעילה | לקוחה לא נמחקת (FR-2.4), "לא פעילה" למקרי קצה בלבד |
| deal | פתוחה → נשלחה חשבונית → שולמה → מבוטלת | "נשלחה חשבונית" הוא הטריגר למשימת הגבייה האוטומטית (build-plan 08) |
| document | טיוטה → נשלח → נחתם/אושר | חל בעיקר על חוזה (נחתם) והצעת מחיר/הזמנה (נשלח) |
| payment | ממתין → שולם → חלקי | ייעודי לתשלום בודד, לא לעסקה כולה |
| subscription | פעיל → הסתיים (10/10 סופקו, **מאושר** FR-3.16/3.17) → בוטל (**מאושר** FR-3.18 מתאר חידוש כעסקה חדשה) |  |
| expense | ממתינה לחשבונית → תועדה | תואם FR-6.7–FR-6.9 (זיהוי הוצאות חסרות חשבונית) |
| material_delivery | טרם נפתח → נפתח → אושר שהתקבל | **מאושר במלואו** — FR-5.10–FR-5.15 |

**כללים עסקיים מרכזיים:** FR-7.7, FR-7.8, FR-7.12, עיקרון 1.6.12.

**תלויות:** שלב 1.

**הגדרת סיום:** אפשר ליצור/להשבית סטטוס, מקור ליד, אמצעי תשלום, עוסק פטור ותבנית דואר; השבתה לא מוחקת רשומות שכבר משתמשות בערך הישן; לאחר seeding המערכת מכילה נתוני ייחוס תקינים מוכנים לשימוש.
