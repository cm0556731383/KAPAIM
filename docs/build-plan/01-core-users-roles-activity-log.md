# שלב 1: ליבת מערכת — משתמשות, תפקידים, הרשאות, יומן פעילות

**ישויות:** `USER`, `ROLE`, `ROLE_PERMISSION`, `ACTIVITY_LOG`.

**מה נבנה בפועל:**
- Auth (login בלבד — אין הרשמה עצמית; המשתמשות נוצרות ידנית).
- מודל `Role` + `RolePermission` (resource/action/is_allowed) כך שב-MVP קיים תפקיד אחד "גישה מלאה" לשתי המשתמשות (בעלת העסק, מזכירה), אבל המנגנון תומך בהוספת תפקיד "עובדת מכירות" מוגבל בעתיד (סעיף 1.3.12, 3.4) בלי לשנות ארכיטקטורה.
- Middleware/Policy גנרי שבודק הרשאה לפי resource+action, כך שפעולה לא-זמינה **לא נעלמת** אלא מוצגת כ-disabled (עיקרון 3.12).
- `ActivityLog`: שירות מרכזי (`ActivityLogger`) שכל מודול עתידי יזרים אליו אירועים. טבלה עם FK אופציונליים לכל הישויות (school/lead/customer/deal/subscription/...), לא ניתנת לעריכה/מחיקה ברמת DB (ללא update/delete מותרים ב-policy, ואין UI לכך).

**כללים עסקיים מרכזיים:** FR-7.17–FR-7.20 (יומן כרונולוגי, לא ניתן לעריכה), FR-7.1–FR-7.6 (MVP: הרשאה מלאה זהה לשתי המשתמשות).

**תלויות:** שלב 0.

**הגדרת סיום:** ניתן להתחבר כשתי משתמשות, שתיהן רואות הכל; קריאה ל-`ActivityLogger::log(...)` יוצרת רשומה שאינה ניתנת לעריכה; יש מודל Role/Permission שאפשר להרחיב ללא מיגרציה נוספת.
