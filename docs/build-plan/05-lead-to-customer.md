# שלב 5: המרת ליד ללקוחה + כרטיס לקוחה

**ישויות:** `CUSTOMER` (נגזר מ-`LEAD`).

**מה נבנה בפועל:**
- פעולת "המרה ללקוחה": יוצרת `CUSTOMER` עם `lead_id` FK, **לא** מוחקת/משכפלת את הליד; ליד יכול להיות מומר פעם אחת בלבד (FR-1.15, US-004).
- מסך כרטיס לקוחה מרכזי (3.7): פרטי ביה"ס, אנשי קשר, סטטוס מנוי (placeholder עד שלב 8), עסקאות, מסמכים, תשלומים, יתרת חוב, חומרים, היסטוריית פעילות — כרגע רוב הטאבים ריקים/stub, יתמלאו בשלבים הבאים.
- כלל: לכל לקוחה חובה לפחות איש קשר ראשי אחד; לא ניתן להסיר סימון מהראשי האחרון (FR-2.8, FR-2.9).
- סניף רשת חינוך = כרטיס לקוחה נפרד גם אם התשלום מרוכז ברמת הרשת (FR-2.2) — נאכף כהנחיה תפעולית, לא כמגבלת סכימה.

**כללים עסקיים מרכזיים:** FR-2.1–FR-2.18, US-004, US-005, FR-8.2 (לא ניתן ליצור לקוחה ידנית שלא מהמרת ליד), FR-8.3 (לקוחה לא נמחקת).

**תלויות:** שלב 4.

**הגדרת סיום:** המרת ליד יוצרת לקוחה עם היסטוריה שמורה; אין דרך ב-UI ליצור לקוחה ישירות או למחוק לקוחה קיימת.
